# Стек: hawser

[🇬🇧 English](README.md) · 🇷🇺 Русский

Edge-агент Hawser как стек Dockhand From-Git — чтобы у его compose-файла был один
дом, а правки доезжали до флота опросом, а не руками.

## ⚠️ Этот стек и есть механизм доставки всех остальных

Прочитайте это прежде, чем трогать. Hawser — то, с чем разговаривает Dockhand;
всё остальное здесь приходит *через* него. Два следствия, которых нет ни у одной
другой папки репозитория:

**Плохой мёрдж здесь ломает управление всеми хостами сразу,** на следующем
опросе, и починить это из Dockhand нельзя — исправление пошло бы через только что
сломанного агента. Восстановление — прогон Ansible по хосту, через SSH:

```bash
ansible-playbook playbooks/hawser.yml --limit <host>
```

**Передеплой этого стека — это агент, пересоздающий собственный контейнер.**
Команда приходит по тому самому соединению, которое пересоздание обрывает. Сам
контейнер должен выжить — пересоздаёт демон Docker, а не запросивший клиент, — но
доедет ли отчёт о завершении, агент про себя ответить не может. Это поведение
устанавливается на лабораторной ноде; до тех пор не разворачивайте стек в
продакшен-окружении.

## Первая установка отсюда невозможна

Dockhand достаёт до ноды только через Hawser, поэтому ноде без агента агента не
доставить. `roles/hawser` в
[ansible-playbooks](https://github.com/nargothrondir/ansible-playbooks) ставит
агента на голый хост и остаётся путём восстановления — ровно как `roles/semaphore`
для стека `semaphore`.

То есть этот стек роль не заменяет. Он берёт на себя *жизненный цикл* после того,
как роль сделала *bootstrap*.

## Развёртывание

Dockhand → Stacks → **From Git**, путь `hawser`, в окружение нужного хоста.

Стек намеренно **не задаёт `container_name`**. Bootstrap-проект в `/opt/hawser`
занимает имя `hawser`, а явный `container_name` конфликтует между compose-проектами
— Docker просто отказывает второму. Именно отсутствие имени позволяет развернуть
этот стек, пока bootstrap-агент ещё работает, а другого порядка у передачи
управления нет.

## Переменные окружения

| Переменная | Обязательна | Назначение |
|---|---|---|
| `TOKEN` | да, **секрет** | Токен агента, выданный Dockhand для этого окружения |
| `DOCKHAND_SERVER_URL` | да | Точка входа `wss://`, напр. `wss://dockhand.example.com/api/hawser/connect` |
| `STACKS_DIR` | нет (`/opt/hawser-stacks`) | Куда агент пишет разворачиваемые стеки |
| `REQUEST_TIMEOUT` | нет (`120`) | Секунды. Апстримные 30 обрывают From-Git деплой посреди скачивания на медленном хосте |

`TOKEN` должен быть тем токеном, который Dockhand действительно выдал **этому**
окружению. Значение, которое всего лишь выглядит валидным, оставляет хост без
управления: агент стартует, не проходит аутентификацию, и вернуть его может только
прогон Ansible по SSH. Ansible хранит то же значение в OpenBao по пути
`infra/hawser`, ключ — имя хоста в инвентаре.

## Почему пути монтирования одинаковы с обеих сторон

`STACKS_DIR` привязан к одному и тому же пути внутри контейнера и вне его. Это не
аккуратность, а необходимость: агент передаёт пути к compose-файлам демону Docker,
а тот разрешает их в **хостовом** пространстве имён. Другой путь внутри контейнера
оставил бы все разворачиваемые стеки указывающими в пустоту.

Оба монтирования — в длинной форме с `create_host_path: false`, чтобы неверный путь
валил деплой, а не монтировал молча пустой каталог. Или, в случае сокета, не
создавал каталог с именем `docker.sock` и не поднимал агента, который здоров и
слеп.
