# Стек: hawser

[🇬🇧 English](README.md) · 🇷🇺 Русский

Edge-агент Hawser. Эта папка — единственный источник compose-файла агента, и
правится он только здесь. Но, в отличие от всех остальных стеков репозитория,
**Dockhand его не разворачивает.**

## ⚠️ Никогда не создавайте из этой папки стек From-Git

`roles/hawser` в
[ansible-playbooks](https://github.com/nargothrondir/ansible-playbooks) забирает
этот файл по HTTPS на закреплённом коммите и поднимает его по SSH. Это
единственный поддерживаемый путь.

Это не осторожность — это измерено на лабораторной ноде 2026-08-13:

```
2bd614e0a5a9_hawser-hawser-1   Created        <- так и не запустился
hawser                          Exited (0)     <- остановил сам себя
PL-1                            Failed         <- агента нет вовсе
```

Разворачивание этого стека через Dockhand заставляет агента выполнить
`compose up` над проектом, в который входит он сам. Он остановил собственный
контейнер, а замена осталась в состоянии `Created`: процесс, который должен был
её запустить, находился внутри только что остановленного контейнера.
`restart: unless-stopped` тут не помогает — политика не применяется к контейнеру,
который ни разу не стартовал.

Dockhand ответил `Failed to up via Hawser: Connection error` через 1,1 секунды
после отправки запроса, и нода оставалась без управления до прогона Ansible.

Та же логика исключает и первую установку: Dockhand достаёт до ноды только через
Hawser, поэтому ноде без агента агента не доставить.

## Как файл на самом деле попадает на ноду

1. `roles/hawser` скачивает его на закреплённом коммите — репозиторий публичный,
   никаких учётных данных не требуется
2. роль рендерит рядом `.env` со значениями конкретного хоста
3. `docker compose up -d` по SSH

Поэтому правка этого файла доезжает до флота через бамп пина и прогон Ansible, а
не через опрос Dockhand.

## Переменные окружения (`.env`, пишет роль)

| Переменная | Обязательна | Назначение |
|---|---|---|
| `TOKEN` | да, **секрет** | Токен агента, выданный Dockhand для этого окружения |
| `DOCKHAND_SERVER_URL` | да | Точка входа `wss://`, напр. `wss://dockhand.example.com/api/hawser/connect` |
| `STACKS_DIR` | нет (`/opt/hawser-stacks`) | Куда агент пишет разворачиваемые стеки |
| `REQUEST_TIMEOUT` | нет (`120`) | Секунды. Апстримные 30 обрывают From-Git деплой посреди скачивания на медленном хосте |

`TOKEN` — настоящий секрет, и в этом файле его нет: он живёт только в `.env`,
который роль пишет с правами `0600` под `no_log`. Значение, которое лишь выглядит
валидным, оставляет хост без управления: агент стартует, не проходит
аутентификацию, и вернуть его может только прогон Ansible по SSH. То же значение
Ansible хранит в OpenBao по пути `infra/hawser`, ключ — имя хоста в инвентаре.

## Почему пути монтирования одинаковы с обеих сторон

`STACKS_DIR` привязан к одному и тому же пути внутри контейнера и вне его. Это не
аккуратность, а необходимость: агент передаёт пути к compose-файлам демону
Docker, а тот разрешает их в **хостовом** пространстве имён. Другой путь внутри
контейнера оставил бы все разворачиваемые стеки указывающими в пустоту.

Оба монтирования — в длинной форме с `create_host_path: false`, чтобы неверный
путь валил деплой, а не монтировал молча пустой каталог. Или, в случае сокета, не
создавал каталог с именем `docker.sock` и не поднимал агента, который здоров и
слеп.
