# Стек: remnanode

[🇬🇧 English](README.md) · 🇷🇺 Русский

Нода Remnawave + прокси-подложка Angie для reality, TLS-сертификат которой
Angie выпускает сам через ACME DNS-01 — certbot на хосте не нужен.

## Развёртывание

Через Dockhand → Stacks → **From Git**, путь `remnanode`, в окружение целевой
ноды.

## Переменные окружения (задаются по ноде в Dockhand)

| Переменная | Секрет | Назначение |
|---|---|---|
| `SECRET_KEY` | **да** | ключ ноды из панели Remnawave |
| `CF_API_TOKEN` | **да** | DNS-токен, которым ACME-хук отвечает на DNS-01 |
| `ACME_DOMAIN` | нет | родительская зона (например `example.com`); обязательна — без неё деплой падает |
| `NODE_NAME` | нет | короткое имя ноды (например `pl`); обязательна |
| `CAMO_SITE` | нет | какой decoy-сайт отдавать; назначается по ноде конвейером провижининга, `converter` если не задана |

`ACME_DOMAIN` и `NODE_NAME` складываются в `server_name
<NODE_NAME>.<ACME_DOMAIN>`, поэтому **каждая нода выпускает сертификат на своё
имя**, а не делит общий wildcard на весь флот — скомпрометированный токен
одной ноды не позволит выпустить сертификат, действительный для остальных.

Обе объявлены через `:?`, так что отсутствующее значение роняет деплой сразу,
а не рендерит сломанный `server_name`.

## Сертификаты

Встроенный ACME-клиент Angie (`acme letsencrypt`) выпускает и продлевает
напрямую; `ssl_certificate` читает `$acme_cert_letsencrypt` из тома
`angie-acme`. В этом томе лежат **ключ ACME-аккаунта и выпущенные
сертификаты** — его нужно сохранять между редеплоями, иначе каждый деплой
тратит слот дубликата сертификата.

На живой ноде том очищать нельзя: конфиг отдаёт сертификат **из** него, и
пустой том означает отсутствие TLS до завершения выпуска.

## Хук DNS-01

У Angie нет встроенного DNS-провайдера, поэтому проверку отвечает маленький
сервис из `acme-hook/`. Он создаёт и удаляет TXT-запись `_acme-challenge` через
API Cloudflare и является тем самым контейнером, который держит `CF_API_TOKEN`.

Он существует в двух вариантах, и это намеренно:

| | |
|---|---|
| `acme-hook.py` | оригинал. Стоковый образ `python:3.14-slim` со смонтированным скриптом — образ собирать не нужно, а стандартной библиотеки хватает на всю задачу |
| `acme-hook/` | порт того же поведения на Go, собираемый в образ `distroless/static` |

Причина порта — образ, а не язык. В `python:3.14-slim` едут интерпретатор,
пакетный менеджер, shell и userland; в статическом бинарнике на distroless нет
ничего из этого. Для единственного контейнера на ноде, который держит токен
Cloudflare, эта разница и есть весь аргумент — своих зависимостей версия на Go
не приносит, так что больше ничего не меняется.

Цена — конвейер сборки там, где его не было. CI компилирует на каждом
pull request, задевающем `acme-hook/`, и публикует в
`ghcr.io/nargothrondir/acme-hook` при мёрдже; дальше compose пинит digest ровно
так же, как сейчас пинит образ Python.

**`acme-hook.py` остаётся, пока версия на Go не продлит настоящий сертификат.**
Продление наступает на 60-й день, иначе поломка проявилась бы сильно позже
изменения, которое её вызвало. Откат — правка одного блока в compose.

### Как проверить, не дожидаясь продления

Хук управляется только заголовками запроса, поэтому его можно дёрнуть напрямую,
без всякого ACME. На ноде, по работающему контейнеру:

```bash
curl -si -X GET http://127.0.0.1:9001/healthz | head -1
```

```bash
curl -si -X GET http://127.0.0.1:9001/   -H 'X-Acme-Op: add'   -H 'X-Acme-Domain: <имя ноды>.<зона>'   -H 'X-Acme-Keyauth: test-value-please-delete' | head -1
```

`200` и появившаяся в Cloudflare TXT-запись
`_acme-challenge.<имя ноды>.<зона>` означают, что добавление работает; тот же
вызов с `X-Acme-Op: remove` и тем же значением keyauth должен её убрать. Всё,
что вне зоны, обязано отвергаться — этот запрет и не даёт вызывающему направить
проверку на имя, которое нода доказывать не должна.

## Камуфляж reality

Decoy-сайт лежит в самом стеке в `www/` и монтируется только на чтение в
`/var/www/html`. Каждая нода выбирает свой через `CAMO_SITE`, чтобы флот
нельзя было опознать по одинаковой странице.

Значение назначается по ноде конвейером провижининга (`dockhand-stack.yml` в
репозитории ansible-playbooks) и засевается именем ноды, поэтому повторный
прогон не может выбрать другое и передеплоить стек. Уже заданное значение —
выставленное руками в Dockhand — сохраняется, а не перезаписывается. Стек,
развёрнутый вне этого конвейера, откатывается на `converter`.

Монтирование сделано с `create_host_path: false` намеренно: опечатка в
`CAMO_SITE` тогда роняет деплой, а не подсовывает молча пустой каталог —
который отдавал бы пустую страницу и выдавал ноду ничуть не хуже.

### Всё в выбранном каталоге — публично

Angie отдаёт `root /var/www/html` без ограничивающих `location`, а каталог
приманки монтируется туда целиком. Поэтому **любой файл внутри доступен всякому,
кто пробует ноду** — приватных заметок внутри `www/<site>/` не существует.

Пять upstream-файлов `README.md` приехали именно так и здесь удалены:
`curl https://<нода>/README.md` возвращал инструкции по установке с названием
репозитория шаблонов, а это опознаёт страницу как маскировочную надёжнее, чем
когда-либо опознали бы одинаковые страницы на нодах. Проверка 3 в
`stack-guards.sh` теперь роняет сборку на любом неверстальном файле такой
глубины. Заметки уровня репозитория место в самом `www/` (он не монтируется) или
в этом README.

### Происхождение

Сайты-приманки — сторонние шаблоны, и они вендорятся, а не тянутся по сети:
сетевой сбой иначе даёт недорендеренную страницу, что само по себе отпечаток.
Известные upstream этого семейства шаблонов:

- [distillium/sni-templates](https://github.com/distillium/sni-templates)
- [proxyboy228/SNI-Templates](https://github.com/proxyboy228/SNI-Templates)
- `SmallPoppa/sni-templates` — на него ссылались удалённые README, **сейчас удалён**

**Ни у одного из трёх нет лицензии**, поэтому установить разрешение невозможно и
здесь оно не заявляется. Своего `LICENSE` этот репозиторий не несёт: нельзя
лицензировать то, чем не владеешь. Шаблоны указаны как чужие, а не присвоены.

То, что один upstream уже исчез, — причина продолжать вендорить, и причина
завести форк под своим аккаунтом как устойчивую ссылку.

## Примечания

- Прокси слушает `unix:/dev/shm/nginx.sock` — путь, куда пересылает
  xray/reality. **Переименовывать нельзя.**
- Доставка — опросом (плановая синхронизация Dockhand), не входящими
  вебхуками: админ-поверхности остаются приватными по умолчанию.
- Что осталось усилить: токен Cloudflare по-прежнему на всю зону. Сужение
  через делегирование acme-dns описано в issue #25.
