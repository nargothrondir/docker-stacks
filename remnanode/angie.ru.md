# angie.conf — как он устроен и почему

[🇬🇧 English](angie.md) · 🇷🇺 Русский

[`angie.conf`](angie.conf) держится без пояснений; они здесь. Разделы ниже
идут в том же порядке, что пронумерованные разделы конфига. Развёртывание стека,
его переменные и сайты-приманки — в [README.ru.md](README.ru.md).

## Как файл используется

- **Монтируется** как `/etc/angie/templates/http.d/default.conf` и включается
  внутрь блока `http {}` образа — всё в нём либо уровня http, либо блоки
  server.
- **Рендерится gomplate на старте контейнера** (образ `-templated`). Поэтому
  правка доходит до ноды, только когда перезапускается `remnawave-angie`, — см.
  [Правка этого файла](#правка-этого-файла).
- **Синтаксис шаблона — двойные фигурные скобки gomplate**, и gomplate разбирает
  их даже внутри `#`-комментариев: пустая пара в комментарии роняет рендер
  (`missing value for command`). Описывайте синтаксис словами.
- **Входы шаблона** читаются один раз, в начале файла:

  | Переменная | Обязательна | Что делает |
  |---|---|---|
  | `NODE_NAME`, `ACME_DOMAIN` | да — без них рендер падает | `server_name` = `NODE_NAME.ACME_DOMAIN`; на это имя выпускается сертификат |
  | `XHTTP_PATH` | нет | рендерит location xHTTP; пусто — xHTTP на ноде выключен |
  | `XHTTP_UPSTREAM` | нет, по умолчанию `grpc` | `grpc` или `http`; любое другое значение роняет рендер |

Трафик через файл:

```
:443/tcp  xray REALITY ──(не REALITY-клиент)──▶ unix:/dev/shm/nginx.sock
              ├─ SNI = имя этой ноды ─▶ [4] decoy-сайт
              │                             └─ XHTTP_PATH ─▶ xray xHTTP inbound
              └─ любой другой SNI ───▶ [5] рукопожатие отклонено
127.0.0.1:9000 ─▶ [6] хук ACME DNS-01 ─▶ сервис acme-hook
```

## 1. Имя сервера

`server_tokens off` убирает версию из заголовка `Server` и со страниц ошибок.
Заменить само имя («Angie») или убрать заголовок можно только в Angie PRO —
открытая сборка принимает лишь `on | off | build`.

`server_names_hash_bucket_size 64` оставляет место для длинных имён нод.

## 2. TLS

Блок TLS в `angie.conf` общий для всех listener'ов, и на этой ноде он больше,
чем шифрование decoy-сайта: **так со стороны выглядит каждый TCP-клиент ноды.**

- REALITY использует рукопожатие своего target как маскировку, а target здесь —
  этот Angie. Если target поддерживает `X25519MLKEM768`, REALITY-клиенты,
  которые её предлагают, тоже её используют (документация Xray, `target` в
  REALITY). Mihomo убирает эту группу из своего REALITY ClientHello, если не
  задан `support-x25519mlkem768` (`component/tls/reality.go`, v1.19.31), так что
  у пользователей Mihomo REALITY в любом случае остаётся на X25519.
- Клиенты xHTTP, браузеры и зонды завершают свой TLS здесь.

Поэтому цель — выглядеть как обычный современный веб-сервер, и профиль взят тот,
по которому настроено большинство таких серверов: **Mozilla «intermediate»,
рекомендации 6.0** (ssl-config.mozilla.org). По сравнению с профилем 5.x,
который стоял в конфиге раньше:

- `X25519MLKEM768` первой среди групп — гибридный постквантовый обмен ключами,
  который предлагают современные браузеры. Нужен OpenSSL 3.5 или новее; в образе
  3.5.x.
- Нет наборов `DHE-RSA-*`. Они и раньше не использовались: DHE нужен
  `ssl_dhparam`, а он не задан.
- `ssl_prefer_server_ciphers off`: все наборы в списке стойкие, поэтому выбирает
  клиент — так же ведёт себя стандартная конфигурация.
- Без OCSP stapling: Let's Encrypt выключил свой OCSP-сервис 2025-08-06 и
  публикует отзыв только через CRL.

`ssl_session_tickets off` и кэш сессий `MozSSL` перенесены из того же профиля.

## 3. ACME-клиент

Let's Encrypt, DNS-01 через хук из [раздела 6](#6-хук-acme-dns-01), поэтому
входящих портов не открывается. Состояние — ключ аккаунта и сертификаты — лежит
в томе `angie-acme`; см. [README: Сертификаты](README.ru.md#сертификаты), там же —
зачем `remnanode` подключает тот же том только на чтение для Hysteria2.

**Директивы `resolver` нет намеренно.** Angie 1.12 сам читает
`/etc/resolv.conf` и следит за его изменениями, а контейнер работает с
`network_mode: host` — значит, это файл хоста, тот же зашифрованный резолвер,
которым пользуются apt, NetBird и всё остальное на ноде. Жёстко прописанный
`resolver 1.1.1.1 8.8.8.8` делал ACME-клиент вторым, независимым путём DNS,
который игнорировал настройки ноды и спрашивал открытым текстом — причём ровно
те запросы, по которым видно, на какое имя и когда выпускается сертификат.
Проверено на проводе (lab-нода, 2026-08-10): без директивы и с очищенным
состоянием ACME весь выпуск дал 16 пакетов к локальной заглушке и 62 к
вышестоящему серверу на 853, ни одного к 1.1.1.1:53 или 8.8.8.8:53.

## 4. Виртуальный хост ноды

Сервер на собственное имя ноды: его сертификат (выпускает и продлевает
раздел 3), заголовок `X-Robots-Tag`, который не пускает приманку в поисковики,
сам decoy-сайт ([README: Камуфляж reality](README.ru.md#камуфляж-reality)) и —
если задан `XHTTP_PATH` — location xHTTP ([README: xHTTP](README.ru.md#xhttp)).

Location xHTTP построчно:

| Строка | Зачем |
|---|---|
| `grpc_pass unix:/dev/shm/xhttp.sock` | HTTP/2 к сокету inbound, тело запроса идёт потоком по мере поступления. Та же схема, что в XTLS/Xray-examples `VLESS-XHTTP3-Nginx` |
| `grpc_read_timeout` / `grpc_send_timeout 1h` | Xray закрывает простаивающие соединения через 300 с и следит за **обоими** направлениями; Angie — за одним потоком. С 315 с из примера он обрывал поток загрузки, молчавший, пока клиент продолжал выгружать (`upstream timed out (110) while reading upstream`, 2026-09-23). Час оставляет решение за Xray |
| `client_max_body_size 0` | POST в packet-up — до 1 000 000 байт (`scMaxEachPostBytes`), ровно на пределе 1m по умолчанию |
| `client_body_timeout 5m` | медленный клиент не обрывается посреди тела POST |
| `X-Real-IP` / `X-Forwarded-For` из `$proxy_protocol_addr` | адрес клиента из PROXY-заголовка, который прислал REALITY. Xray учитывает `X-Forwarded-For`, только если есть заголовок из `sockopt.trustedXForwardedFor` inbound (`X-Real-IP`); оба перезаписываются, так что клиент не может их подделать |
| `access_log off` | в packet-up каждый кусок выгрузки — отдельный POST, а его `Referer` дополнен 100–1000 байтами: ~1 МБ лога за три минуты одного клиента (замер 2026-09-23), и в каждой строке — секретный путь и хронология, кто сколько передал. У decoy-сайта лог остаётся |

`upstream prematurely closed connection` в логе ошибок — нормальное завершение
простаивающего потока xHTTP: Xray закрывает его по своему таймауту простоя, а
xHTTP — не gRPC и трейлеров не шлёт.

## 5. Сервер по умолчанию

Сервер по умолчанию (`default_server`) отклоняет любое рукопожатие, где SNI — не
имя этой ноды, ещё до показа сертификата. Он же закрывает (`444`) запрос, в
котором `Host` не называет ни один сервер, — такой может прийти и после
рукопожатия на имя ноды, и без этого ответил бы сервер по умолчанию.

## 6. Хук ACME DNS-01

Сервер только на loopback, который ACME-клиент вызывает при каждом добавлении и
удалении TXT-записи `_acme-challenge`; запрос уходит заголовками в сервис
`acme-hook`, у которого DNS-токен. Как хук работает и как его проверить —
[README: Хук DNS-01](README.ru.md#хук-dns-01).

## Правка этого файла

Измерено 2026-08-19, и это самое неочевидное свойство этого стека.

`angie.conf` монтируется в каталог шаблонов, а образ `-templated` рендерит его
через gomplate **на старте контейнера**:

```
./angie.conf → /etc/angie/templates/http.d/default.conf → (gomplate) → /etc/angie/…
```

Поэтому правка с последующим переразвёртыванием не даёт видимого эффекта.
Dockhand кладёт новый файл на диск, `docker compose up` сравнивает описание
сервиса, не находит изменений и оставляет контейнер работать — а внутри него
отрендеренный конфиг всё тот же, потому что gomplate с момента старта не
запускался.

Деплой при этом отчитывается успехом. Нода продолжает жить по-старому.

**Чтобы применить правку конфига, перезапустите контейнер:**

```bash
docker restart remnawave-angie
```

`angie -s reload` не поможет: он перечитывает **отрендеренный** файл, а тот
устарел.

С `docker-compose.yml` такой проблемы нет — это изменение описания сервиса,
поэтому compose пересоздаёт контейнер и gomplate отрабатывает. Затронуты только
правки конфигов, то есть ровно тот случай, когда ничто не выглядит сломанным.

CI рендерит файл образом Angie `templated` для каждого варианта необязательных входов — без
xHTTP, xHTTP через `grpc`, xHTTP через `http` — запускает на каждом `angie -t` и
проверяет, что `XHTTP_UPSTREAM=bogus` роняет рендер.
