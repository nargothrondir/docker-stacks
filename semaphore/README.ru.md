# Стек: semaphore

[🇬🇧 English](README.md) · 🇷🇺 Русский

Semaphore (веб-UI для Ansible) на управляющем хосте, развёрнутый как
From-Git-стек Dockhand.

## Развёртывание

Dockhand → Stacks → **From Git**, путь `semaphore`, в окружение управляющего
хоста. Слушает `127.0.0.1:3030` и публикуется обратным прокси хоста — наружу
напрямую не смотрит никогда.

## Секреты (secret env vars в Dockhand)

| Переменная | Назначение |
|---|---|
| `SEMAPHORE_ADMIN_PASSWORD` | первоначальный пароль администратора |
| `SEMAPHORE_ACCESS_KEY_ENCRYPTION` | base64, 32 байта — шифрует Key Store |

Потеря `SEMAPHORE_ACCESS_KEY_ENCRYPTION` делает нечитаемыми все хранимые
SSH-ключи и пароли vault. Ей место в менеджере паролей, а не только в
Dockhand.

## ⚠️ Внешние тома — не переименовывать

Три тома объявлены `external` и указывают на тома, созданные исходным
развёртыванием через Ansible (compose-проект `semaphore`) — благодаря этому
переезд на From-Git сохранил проекты, Key Store и историю задач.

Переименование (или позволение compose создать новые) молча запустит пустой
Semaphore, пока настоящие данные останутся в осиротевших томах.

## Тонкость самообновления

Dockhand пересоздаёт этот контейнер через сокет Docker — так управляющая
плоскость обновляет сама себя. Два следствия, о которых стоит знать:

- Обновление **самого движка Docker** на этом хосте перезапускает демон и
  убивает выполняющийся прогон Ansible — включая тот, который это обновление
  и выполняет. Нельзя пускать плановое обновление флота на управляющий хост
  без присмотра.
- Роль `roles/semaphore` в репозитории `ansible-playbooks` остаётся путём
  аварийного восстановления: она поднимает всё это с чистого хоста.

## Сеть OpenBao

Стек входит во внешнюю docker-сеть `openbao-net`, которую создаёт роль
`roles/openbao` в `ansible-playbooks`, и обращается к хранилищу секретов по
адресу `http://openbao:8200`.

Semaphore читает секреты **от имени** плейбуков, поэтому клиентом, которому
нужен API, является он, а не целевой хост. OpenBao публикуется только на петле
панели, куда контейнеру не достучаться; публикация на шлюзе моста открыла бы
хранилище всем контейнерам хоста.

Сеть должна существовать до развёртывания стека — сначала примените
`roles/openbao`.
